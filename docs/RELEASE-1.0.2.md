# Release 1.0.2

Fixes the remaining Windows default-wallpaper flash and blank preview when switching videos in 1.0.1.

## What's changed

- Video-to-video changes reuse one owned MPV process/GPU window. `loadfile replace` closes the previous media and decoder; switching to an image, memory-saving release and shutdown still terminate the owned renderer.
- The outgoing image is held in a layered native child, independently composed by DWM, until the new video has a decoded frame. The capture is limited to 2,073,600 pixels; the display-sized staging DIB is capped at 64 MiB and released after upload.
- Preview keeps its renderer and shows the selected thumbnail while loading. It becomes ready after a decoded frame, rather than the file-open notification. Closing/removing preview waits asynchronously for process exit before destroying its native surface.
- Rapid requests serialize; media versions and start-file/file-loaded barriers suppress stale frames, EOF and failures. Subscribers bind once per renderer. Diagnostics restart for each media load.
- Still-image preview decoding is bounded while original dimension metadata remains accurate.

## Validation

- Build/publish: zero warnings/errors. Core: 23/23 groups.
- Native transition suite: video renderer reuse, image release, missing/broken targets, retained frame, rapid requests, EOF, resizing and disposal.
- Native preview suite: real playback, renderer reuse, first-frame readiness, seek/pause, rapid image selection, hide/reopen, invalid media and process cleanup.
- 48 native video replacements: one renderer, hardware decoding confirmed; app warm-to-end median private-memory change -2.79 MiB, handles -6. Renderer memory/handle growth passed bounded short-run checks. This is not an 8/24-hour soak.
- 20 mixed H.264/HEVC/VP9/AV1 replacements: one PID, correct current media/codec, hardware decoding and first-frame readiness. Exclusive opening of each outgoing file confirms its handle was released.
- Physical desktop recording: inspected the recorded handoff at 30 fps; the old wallpaper changes directly to the new one without the previously reported default-wallpaper gap in that captured case. Two real 4K replacements logged first-frame decode times of approximately 57 and 67 ms. These times exclude capture/bridge preparation and are not universal switch latency guarantees.

Physical multi-monitor/mixed-DPI, cold boot, sleep/lock/Explorer recovery under load and long soak remain open. Hardware decoding depends on GPU/codec. See VALIDATION.md for package checks.

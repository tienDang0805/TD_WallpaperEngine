# TD_Wallpaper 1.0.4

The application now uses **TD_Wallpaper** throughout its source projects, namespaces, executable, UI, build scripts and distribution filenames.

## Downloads

- `TD_Wallpaper-1.0.4-Setup.exe`: per-user Windows installer.
- `TD_Wallpaper-1.0.4-Portable.zip`: extract all files and run `TD_Wallpaper.exe`.
- `SHA256SUMS.txt`: checksums for both packages.
- Source ZIP and tar.gz: generated by GitHub for tag `v1.0.4`.

Exit the previous app from its tray menu before updating. Keep the files accompanying the portable EXE together.

## Compatibility

- Existing `%LOCALAPPDATA%\TienDangWallpaper` libraries are reused in place. Their wallpaper paths, settings and backups are not rewritten or moved.
- Fresh libraries use `%LOCALAPPDATA%\TD_Wallpaper`. Explicit `--data-dir` libraries work as before.
- The app recognizes its old startup registry entry and replaces it with a `TD_Wallpaper` entry pointing to the current EXE. Installer upgrades migrate an old entry pointing into the installation directory, retaining its arguments, including any data directory.
- Installer AppId, library mutex and desktop/taskbar ownership names stay compatible with older releases. These identifiers are intentionally retained to prevent competing instances and preserve the upgrade/uninstall relationship.
- Setup removes obsolete application binaries and shortcuts from the installation directory. It does not remove wallpaper libraries or media.
- The GitHub repository URL and historical release filenames remain valid.

## Validation

Build and publish: zero warnings/errors. Core tests: 23/23 groups. Naming regression verifies assembly names, embedded English resources, fresh and legacy data directory selection, explicit data directories and startup ownership parsing.

Controller, cross-process desktop ownership, native wallpaper transitions, single-video looping/pause/resume and taskbar preference regressions pass. The self-contained EXE passes all five isolated fresh/startup/existing/backup library smoke cases.

Installer compilation and package content/checksum verification are recorded with the local release artifacts. A physical upgrade of the owner's installed app was not performed; startup migration and removal of old installation files should also be checked on a disposable Windows installation. Earlier unverified Windows 10 taskbar and multi-monitor cases remain open.

## Developer continuation

Open `TD_Wallpaper.slnx`. Application source is in `src/TD_Wallpaper.App`, core logic in `src/TD_Wallpaper.Core`; test projects use the same prefix. Build with `./build.ps1 -Portable`, package with `./package-release.ps1 -Version 1.0.4` and an Inno Setup 6 compiler.

Keep the retained compatibility identifiers stable until a deliberate migration strategy replaces them. Video changes continue reusing the renderer while releasing the old decoder; the naming change does not alter playback architecture.
